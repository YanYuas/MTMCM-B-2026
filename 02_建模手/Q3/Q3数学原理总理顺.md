## 一、从问题到模型：Q3 的目标不是“算 95%”

题目要四样东西：

1. 触发时间的 95% 区间；
2. 预警时间；
3. 区间覆盖率；
4. 空间距离范围。

但数据只给：

- 2 个本地事件（2026 冰崩、2025 GLOF）；
- 84 个无发生时间的沟域多边形；
- 站点/再分析/CHIRPS，但两次事件都非降雨触发；
- 当前预报是 2026-10-24 的未来 72 h，不能回填 2026-08-26。

所以 Q3 的正确目标不是“用 2 个事件拟合一个 95% 覆盖率”，而是：

> **定义一个可计算的触发时间随机变量，给出可解释的预测区间，并明确哪些覆盖率在当前附件下不可识别。**

这就是 A+C 的出发点。

## 二、为什么是 A+C

### 2.1 A：物理 first-passage 给主结果

- 触发时间是“首次满足判据”的**首达时间**（first-passage），不是分类标签；
- 降雨分支可以用 `m_cr`/I-D/API/土壤水计算；
- 冰崩/GLOF 分支没有源区连续观测，只能用“检测时刻 + 检测延迟”的条件情景；
- 多驱动/多参数抽样给出集合，2.5/97.5 分位给区间；
- 与 Q2 阈值、Q4 传播时间天然衔接。

### 2.2 C：代理共形校准给方法可信度

- 事件级覆盖率不可估计，但“区间构造 + 覆盖率评估”流程可以用代理任务验证；
- 选 24 h 降水/6 h 气温等代理，用 split conformal 给 95% 区间；
- 在独立年份上报告经验覆盖率；
- **代理覆盖率 ≠ 事件级覆盖率**，论文必须分开写。

### 2.3 为什么不是 B

B 需要 ≥5–10 个可信事件日期，才能做生存/共形事件级覆盖率。当前只有 2 个本地事件，且 84 个多边形无时间；硬上 B 会踩“伪造标签/伪 95%”红线。B 只作为展望，给算法与数据需求。

## 三、为什么是“预测区间”，不是“置信区间”

- **置信区间**：参数（如均值、阈值）的不确定性；
- **预测区间**：未来随机变量 `T_trigger` 的不确定性；
- Q3 要的是后者。论文首次出现写“95% 预测区间（prediction interval）”，不写“参数置信区间”。
- 区间由集合分位构造，不是从多次事件频率校准；因此不能声称“事件级 95% 覆盖”。

## 四、竞争风险与删失

### 4.1 竞争风险

```
T_trigger = min(T_rain, T_ice, T_glof)
```

三个分支是竞争关系：谁先满足判据，谁决定触发时间。2026 冰崩、2025 GLOF；降雨分支不触发。若只做降雨，会把两次事件都判“未触发”。

### 4.2 删失

若所有分支 `∞`，`T_trigger=∞`。不能把 `∞` 丢掉只对有限样本取分位，否则区间偏窄、覆盖率虚高。必须报告 `p_inf=P(no trigger)`；若 `p_inf>2.5%`，95% 区间上界记 `∞`。

### 4.3 命题 1（首达时间单调性）

若 `I_rain(t)` 固定、阈值 `I_c` 降低，则 `T_rain` 不增（更早触发）。因此阈值区间下界对应最早触发、上界对应最晚触发；集合分位应覆盖这一单调性。论文用敏感性验证，不写“阈值已标定”。

## 五、预警规则：为什么不能事后倒推

`L=T_impact-T_warn` 中的 `T_warn` 必须是**发布规则**的结果，不能是“事件前随便挑一个时刻”。本文用：

```
T_warn = min{ t0 : P(T_impact ≤ t0+H_warn | F(t0)) ≥ p_warn }
```

- `F(t0)` 只用 `t0` 之前的信息；历史回放不能偷看未来；
- `H_warn` 是预警视野，`p_warn` 是决策阈值；
- 若未达到阈值：`T_warn=∞`，`L=NA`，不能记 0；
- 若 `T_warn>T_impact`：迟报，`L<0`，不能当正 lead time。

**命题 2**：在 `p_warn` 固定、`H_warn` 增大时，`T_warn` 不增（更早预警），但虚警概率增加；论文给 `H_warn` 敏感性，不写“最优预警时间”。

## 六、覆盖率为什么不可识别

事件级覆盖率需要多次独立事件：

```
π_event = (1/n) Σ 1[T_event ∈ I_95]
```

`n=2` 时，`π_event` 只能是 0、0.5、1；其抽样误差极大，不能估计 95%。本文：

- 明确写“事件级覆盖率不可识别”；
- 只报“2 个案例是否落入区间”（案例包含性），不写覆盖率；
- 代理覆盖率用独立年份计算；
- 设计覆盖率 0.95 只作方法说明。

**命题 3（共形覆盖）**：在可交换性下，split conformal 的边际覆盖率为 `1-α`；代理任务满足可交换性时可用，但不能把代理覆盖率迁移到事件级。

## 七、空间范围为什么必须拆

“空间距离范围”至少三个尺度：

1. `D_arrival`：源区→口岸/下游的沿程到达距离；
2. `D_impact`：流深/流速超过影响阈值的范围；
3. `R_warn`：预警覆盖半径 = 到达距离 + buffer/监测半径。

三者物理含义不同，不能用一个数代替。Q4 未完成时用情景区间，标 `[C]`；不把 Q4 包络当实测。

## 八、能得出什么、不能得出什么

### 能得出

- 降雨分支的 first-passage 与负控制；
- 竞争风险下 `T_trigger/T_impact` 的集合预测区间；
- 明确发布规则下的 `T_warn/L` 时间线；
- 代理任务的共形覆盖率/区间宽度；
- `D_arrival/D_impact/R_warn` 的情景范围；
- 2026/2025 的案例分支一致性。

### 不能得出

- 事件级 95% 覆盖率；
- “2026 事件由降雨触发”；
- “冰崩/GLOF 的释放时间是从气象数据预测的”；
- “平均预警时间/漏报率/虚警率”（n=2）；
- “Q4 包络是实测到达范围”；
- “阈值已标定/区间是参数置信区间”。

## 九、与 Q1/Q2/Q4 的关系

- Q1：VWC/API/正积温作输入；Top5 不作权重。
- Q2：`m_cr`/I-D/冰崩筛选作判据；`S` 不作触发概率。
- Q4：`T_travel/D_arrival/D_impact` 回填；Q3 先给情景。
- 论文：Q3 是“时间维度的不确定性包装”，不是“又一个分类模型”。
