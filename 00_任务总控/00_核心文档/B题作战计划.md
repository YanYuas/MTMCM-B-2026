## 0. 一句话战略

**以“可识别性优先”为主线：Q1 找可观测异常，Q2 定物理阈值与空间易发，Q3 把“预报”拆成可验证的区间与不可验证的边界，Q4 用守恒仿真给情景包络；全篇用“观测统计 / 代理实验 / 未标定情景”三级标签，避免把一次灾害伪装成训练集。**

B 题真正的难点不是算法不够高级，而是：

- 只有 **一次** 已知灾害（2026-08-26）；
- 历史灾点是 **沟域多边形**，没有发生时间；
- 小时数据有缺测、时区/坐标/QC 码本未给；
- 题目却要求 Q3 给出 **95% 区间、覆盖率、预警时间**。

所以本计划的第一原则是：**能算的算准，不能算的明确说不能算，并给出“数据补齐后怎么做”的可执行路径。**

### 2.1 八项附件怎么用

| (4) 冰川 nc | 30 m 地形/冰厚/速度 | 高 | 冰厚估算；速度为气候态 | Q2 物源、Q4 释放区 |
| (5) 土地覆盖 | 2020–2023 四期 | 高 | 无类别图例，保留原编码 | Q2 地表阻力/易发性 |
| (6) 历史灾点 | 84 个沟域多边形 | 中 | **无发生时间**；只有解译/影像时间 | Q2 空间标签；不能做 Q3 时间标签 |
| (7) DEM | 约 30 m | 高 | 获取时点不明，不一定是灾前 | Q2 地形因子；Q4 地形 |
| (8) 人口 | 县级 17,536 人 | 低 | 无居民点 | 仅作县级暴露背景，不做精确伤亡 |

### 2.2 必须先核的 7 件事

1. **缺测规则**：9999.9、NaN、QC=8 各代表什么；逐变量/逐年的缺测率；缺测不转零。
2. **时间基准**：原始时间字符串是北京时间、尼泊尔时间还是 UTC；事件时刻 10:30 与小时网格如何对齐。
3. **2026 有效截止**：年末时间网格后段是否为空行；不要用未来空白行。
4. **历史灾点**：CRS、字段含义、`解译Time`/`影像Time` 的区别；84 个多边形中落在 DEM 范围内的数量。
5. **DEM**：CRS、分辨率、获取时点；统一重投影到 UTM 45N 再做坡度/汇流。
6. **RAR**：包含哪些时段/分幅；先 `7z l`，按需解压一个分幅评估耗时。
7. **外部数据**：Open-Meteo/GFS/CHIRPS/Sentinel-2 是否可达；失败要留记录，不伪造。

### 2.3 证据分级（全篇强制）

| 级别 | 含义 | 允许的表述 | 禁止的表述 |
|---|---|---|---|
| **A 观测统计** | 直接由附件计算，QC 明确 | “事件窗口相对同季节背景的标准化差异为…” | “证明泥石流由 X 引起” |
| **B 代理实验** | 用代理标签/代理变量验证方法 | “在代理任务上覆盖率 95.3%，不代表事件级覆盖率” | “泥石流触发时间覆盖率 95%” |
| **C 未标定情景** | 参数未标定，只做情景 | “在给定参数下的传播范围为…” | “预报/复现了真实灾害” |

> 每张图、每张表的标题都要带 `[A]`/`[B]`/`[C]`。这是本队区别于“堆模型”的核心卖点。

## 3. 四问作战方案

### 3.1 Q1：边界层过程与事件关联（Top5 特征）

**题目要什么**：基于 MET/RADM/SOIL/FLUX，分析大气边界层结构、天气过程、极端气象事件与吉隆泥石流的关联性，给关联性排序最高的 5 个特征。

**本质**：特征工程 + 关联排序，不是预测。只有一次事件，不能训练分类器。

**方法路线**：

1. **QC 与对齐**：逐变量缺测率；小时网格；事件窗口 `2026-08-26 10:30 ± 72h`；同季节基线取 ±15 天、同时刻（±1h）匹配，避免日变化混入。
2. **物理特征体系**（每组 3–6 个，先少后多）：

| 组 | 特征示例 | 物理意义 |
|---|---|---|
| 边界层动力 | 1/2/4/10/20 m 风速、风切变、风向、 bulk Richardson 数、稳定度类别、TKE、u\*、摩擦速度 | 湍流混合与动量输送 |
| 辐射 | 净辐射 `Rn = Rsd - Rsu + Rld - Rlu`、反照率、云量代理、地表加热 | 融水/热力驱动 |
| 土壤水热 | 5 层 VWC、5 层土壤温度、温度梯度、地表热通量 G、40 cm VWC、土壤储水异常 | 前期含水量与融水入渗 |
| 湍流/通量 | H、LE、VPD、H2O 密度、fetch、波文比 | 感热/潜热分配 |
| 降水/积温 | 1h/24h/72h 降水、24h/72h 正积温、度日融雪指数、前期降水指数 API | 触发与前期累积 |

3. **关联性定义**（必须写清，不能只说“相关”）：
   - 主指标：事件窗口相对同季节基线的**稳健标准化差异**（median/MAD 或 Huber z）；
   - 辅助指标：Spearman、距离相关、互信息；
   - 不确定性：按年 block bootstrap、leave-one-year-out；BH 多重检验校正；
   - 排序：`score = |effect size| × rank stability × 物理可解释性 × 非冗余性`。
4. **Top5 选择**：报告每个特征的中位排名、95% 排名区间、是否在 ≥70% bootstrap 中留在前 5；给出“入选/落选”的理由，而不是只给名单。
5. **验证**：
   - 已知答案检查：净辐射分量闭合、昼夜循环、能量平衡闭合度；
   - 合成异常注入：人为把某个特征在事件窗口抬高，检验排序能否找回；
   - 缺测敏感性：去掉缺测率最高的年份/变量，看 Top5 是否稳定。

**交付物**：特征表（含公式/单位/缺测率）、Top5 排序表（含排名区间）、事件窗口时序图、异常热图、排名稳定性图、风玫瑰/辐射收支图。

**验收标准**：
- Top5 在 bootstrap 中排名稳定（≥70% 留在前 5）；
- 每个特征有物理意义，不是纯数据挖掘；
- 不把“相关”写成“因果”；
- 图数只来自模型，不硬编码。

**主要风险**：单事件 + 多重比较导致排序不稳；自相关导致有效样本变小；缺测导致窗口偏移；把日变化/季节变化误当异常。

### 3.2 Q2：临界条件与空间易发性

**题目要什么**：自行补充卫星遥感、天气预报等数据；根据触发条件研究关键参数临界条件；构建触发评估模型；讨论时间/空间尺度可靠性。

**本质**：物理阈值 + 空间易发性；不是“用 84 个多边形训练一个发生概率模型”。

**方法路线**：

1. **补充数据**（按可用性排序）：
   - 降水：Open-Meteo 历史/预报、GFS/ECMWF、CHIRPS/GPM；
   - 卫星：Sentinel-2/Landsat（土地覆盖/冰川/地表水）、Google Earth Engine；
   - 冰川：附件(3)(4)；
   - 气象：附件(1)(2)。
   - 若接口被阻断：保留失败记录，改用附件 + 文献阈值，**不伪造补充数据**。
2. **物理临界条件**：
   - 无限边坡稳定：`FS = [c' + (γ_sat z - γ_w z_w) cos²β tanφ'] / [γ_sat z sinβ cosβ]`；令 `FS=1`，解临界饱和比 `m_cr = z_w/z`。
   - 降雨-入渗：线性水库/Green-Ampt，把降雨转成土壤含水率/饱和比；触发条件 `m(t) ≥ m_cr`。
   - 经验阈值：`I = a D^{-b}`（强度-历时）；无事件日期时只能引文献/邻区，标注“未标定”。
   - 组合判据：前期含水量高 + 短时强降雨 + 坡度/汇流条件满足。
3. **空间易发性**：
   - 标签：84 个历史沟域多边形 = 已登记正例；负例取未登记沟域/像元，明确“登记偏差”；
   - 特征：坡度、起伏度、沟长、汇水面积、曲率、土地覆盖、冰川覆盖、历史扇、沟口高程；
   - 模型：逻辑回归（可解释基线）+ ExtraTrees/RF（非线性）；类别不平衡处理；
   - 验证：**空间块交叉验证 + 2 km 缓冲**，避免相邻像元泄漏；AUC/PR-AUC/校准曲线；
   - 输出：易发性图 + 阈值曲线；表述为“登记沟域可分性/条件易发性”，不是真实发生概率。
4. **时空尺度可靠性**：
   - DEM 30/60/90 m 重采样；
   - 降水产品 0.1°/0.05°、1h/3h/24h 聚合；
   - 空间块大小/缓冲半径；
   - 报告指标随尺度的变化范围，而不是单个最优值。

**交付物**：研究区/DEM 图、临界阈值曲线（m_cr–β、I–D）、易发性图、ROC/PR/校准图、尺度敏感性表。

**验收标准**：
- 空间块 CV，无相邻像元泄漏；
- 不把像元数当事件数；
- 不把登记倾向当发生概率；
- 阈值参数有来源（文献/物理推导/情景），标注是否标定。

**主要风险**：标签偏差；空间泄漏；DEM/降水尺度不匹配；外部数据不可得；把“易发性”写成“预报”。

### 3.3 Q3：预报、95% 区间与预警（见第 4 节三方案）

**题目要什么**：构建吉隆泥石流预报模型；给触发时间 95% 区间；给预警时间、区间覆盖率、空间距离范围。

**先定义四个对象**（否则论文一定被追问）：

| 对象 | 建议定义 | 注意 |
|---|---|---|
| 触发时间 `T_trigger` | 沟道/坡面首次满足触发判据的时刻 | 不是“灾害被发现的时刻” |
| 95% 区间 | 触发时间的预测区间（prediction interval） | 严格说不是参数置信区间；首次出现时说明 |
| 预警时间 `L` | `T_impact - T_warn`；`T_impact = T_trigger + T_travel` | 必须定义预警发布规则，否则是任意数 |
| 区间覆盖率 | 验证集中真实触发时间落入区间的比例 | 单事件只能得 0/1，不能估 95% |
| 空间距离范围 | 建议拆成“到达距离”“影响范围”“预警覆盖半径”三个量 | 不要用一个“空间范围”混写 |

**核心结论（必须写进论文）**：附件只有一次已知灾害、历史灾点无发生时间，因此**事件级 95% 覆盖率不可识别**。可做的是：物理集合区间 + 代理任务校准 + 明确边界。具体选型见第 4 节。

### 3.4 Q4：守恒型情景仿真

**题目要什么**：构建仿真环境；设定明确关键参数；给仿真过程与可视化结果。

**本质**：给定初始/边界条件下的情景推演，不是“复原真实灾害”。

**方法路线**：

1. **控制方程**：深度平均质量/动量方程；Voellmy 阻力（`μ` 库仑 + `ξ` 湍流）；可选侵蚀/夹带。
2. **数值格式**：有限体积；HLLC/Roe 通量；wet-dry 界面；正性限制器；CFL 自适应；DEM 地形源项 well-balanced 处理。
3. **情景设置**：
   - 释放体积：如 1×10⁵、5×10⁵、1×10⁶ m³；
   - 阻力：`μ ∈ [0.05, 0.30]`，`ξ ∈ [500, 2000] m/s²`；
   - 释放区：冰川/冰崩源区；
   - 组合成 9–11 组情景，不是“一个最优参数”。
4. **验证**（必须做，否则是“漂亮动画”）：
   - 质量守恒：`|M(t)-M(0)|/M(0) < 1%`；
   - 零动量测试：无驱动时不得靠数值扩散“跑远”；
   - 网格收敛：30/15/7.5 m，检查到达距离/流深收敛；
   - 解析/半解析算例：溃坝/斜坡流；
   - 若已知事件影响范围，做叠合对比，标注“情景包络 vs 观测范围”。
5. **输出**：最大流深、最大速度、到达时间、到达距离、淹没范围、过程动画/多帧图、3D 地形叠加。

**交付物**：控制方程与离散说明、参数表、情景矩阵、验证表、淹没/到达时间图、3D 可视化、动画（支撑材料）。

**验收标准**：
- 质量守恒误差 <1%；
- 网格收敛；
- 零动量测试通过；
- 参数标注“未标定情景”；
- 不把情景结果写成预报。

**主要风险**：数值扩散导致假跑远；质量不守恒；参数不可识别；DEM 误差；动画好看但无数值验证。

## 4. Q3 口径三方案（核心决策）

> **决策截止：2026-10-25 12:00。** 这个选择会反推 Q1/Q2 的标签与特征设计，不能拖。

### 4.1 方案 A：物理阈值 + 集合预报（first-passage）

**定义**：

- 触发指标 `I(t)`：前期有效降水/土壤含水率 + 当前雨强 + 融水；
- 临界值 `I_c`：由 Q2 的物理阈值或文献 I-D 曲线给出；
- `T_trigger = inf{ t : I(t) ≥ I_c }`；
- 用集合降雨预报（GFS/ECMWF/Open-Meteo ensemble）驱动，Monte Carlo 抽样阈值、初始含水率、滞后参数；
- 95% 区间 = `T_trigger` 集合分布的 2.5%/97.5% 分位数；
- 预警时间 `L = T_impact - T_warn`，`T_impact = T_trigger + T_travel`（Q4 给传播时间）；
- 空间距离范围 = Q4 情景包络的到达距离/影响范围。

**数据需求**：集合降雨预报、土壤水分/前期降水、Q2 阈值、Q4 传播时间；历史事件用于 hindcast（可选）。

**验证**：
- 合成事件/历史 hindcast 的区间覆盖率；
- 阈值/参数敏感性；
- 与 Q2 物理阈值一致性检查。

**优点**：直接回答问题；物理可解释；与 Q2/Q4 闭环；能给出“预警时间”和“空间范围”的物理链条。

**缺点**：需要预报数据；阈值未标定；集合离散度可能偏窄；事件级覆盖率仍不可估，只能报告 hindcast/代理覆盖率。

**适用**：能拿到预报数据，且团队接受“区间是集合预测区间”的表述。

---

### 4.2 方案 B：统计/生存模型 + 共形校准（事件目录）

**定义**：

- 建立事件目录：日期 + 地点 + 规模；定义非事件日/非事件沟域；
- 离散时间 hazard：`λ(t|X)`（Cox 或 logistic hazard）；
- 生存函数 `S(t) = exp(-∫λ)`；
- 95% 区间：bootstrap 或共形生存预测（conformal survival）；
- 覆盖率：leave-one-event-out 的 empirical coverage；
- 预警时间：hazard 超过决策阈值的时刻到事件时刻；
- 空间范围：Q2 易发性 + Q4 到达范围。

**数据需求**：≥5–10 次可信事件日期（新闻、政府通报、EM-DAT、遥感解译），非事件日，协变量。

**验证**：留一事件覆盖率、校准曲线、时间外推（用较早事件训练、较晚事件测试）。

**优点**：统计上最规范；覆盖率可检验；直接回应“95%”；审稿人最认。

**缺点**：7 天内补事件目录很难；事件日期可能不可靠；少于 5 次事件时不可识别；容易踩“伪造标签”红线。

**适用**：能在 D2 前拿到足够、可信的事件日期；否则不要硬上。

---

### 4.3 方案 C：代理任务 + 明确边界（参考稿路线）

**定义**：

- 选一个可预测的代理 `Y`（如 6h 气温、24h 降水），用分位数回归/共形预测给 95% 区间；
- 在独立年份（如 2025）上报告覆盖率（参考稿给的是 95.34%，但那是代理任务，不是灾害触发时间）；
- 同时给出“若未来有事件标签，触发时间区间如何计算”的算法（伪代码/流程图），明确当前不可识别，不伪造标签。

**数据需求**：附件即可；不需要事件目录。

**验证**：独立年份覆盖率、区间宽度、校准曲线；代理任务的已知答案检查。

**优点**：附件即可完成；诚实；可复现；完全避开“伪造标签”红线；方法学完整。

**缺点**：可能被评委认为“没有回答 Q3”；需要强论证和“数据补齐后可执行”的路径；不能给 2026 事件的具体 95% 区间。

**适用**：时间紧、数据无法补充、团队优先稳。

---

### 4.4 推荐：A + C 混合（B 作为备选分支）

**主路径**：

1. **A 给主结果**：用物理阈值 + 集合预报，给 `T_trigger` 的 95% 区间、预警时间、空间范围；明确“这是集合预测区间，不是事件级频率校准”。
2. **C 给方法校准**：用代理任务（如 6h 气温或 24h 降水）做共形预测，报告独立年份覆盖率，证明“区间构造 + 覆盖率评估”流程可行；明确“代理覆盖率 ≠ 事件级覆盖率”。
3. **B 只在 D2 前拿到 ≥5 个可信事件日期时启用**；否则不碰。

**论文写法**（建议顺序）：

1. 先定义 `T_trigger`、`T_impact`、`T_warn`、覆盖率、空间范围；
2. 给 A 的物理区间与集合方法；
3. 给 C 的代理校准与覆盖率结果；
4. 给 B 的“若有事件目录”的算法与数据需求（可作为展望）；
5. 明确写：**事件级 95% 覆盖率在当前附件下不可识别**；本文报告的是“集合预测区间 + 代理任务覆盖率”，并给出数据补齐后的验证方案。

**决策标准**：

| 标准 | A | B | C | A+C |
|---|---|---|---|---|
| 直接回答题目 | 高 | 高 | 中 | 高 |
| 数据可得性（7 天内） | 中 | 低 | 高 | 中高 |
| 覆盖率可检验 | 中（hindcast） | 高 | 中（代理） | 中高 |
| 红线风险 | 中（阈值未标定） | 高（伪标签） | 低 | 低中 |
| 评委可接受度 | 高 | 高（若有数据） | 中 | 高 |
| 工作量 | 中 | 高 | 低 | 中高 |

**建议**：默认走 **A+C**；如果 10/25 12:00 前确认能拿到 ≥5 个可信事件日期，则把 B 加入作为主验证；如果预报接口完全不可达，则退到 **C 为主 + A 的情景版**。
