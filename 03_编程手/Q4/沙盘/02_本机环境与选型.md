# 本机环境检测与 3D 沙盘选型

> 检测时间：2026-10-24 17:40 | 机器：Windows / AMD64
> 结论：**Web 3D + 本地 Python Q4 求解器是这台机器的最优解；Unreal 只适合离线电影级，不适合本机实时 Pixel Streaming。**

### GPU 判断

- RTX 5060 Laptop 8 GB 是 **UE5 的最低可用档**：小场景、关闭 Lumen/Nanite 全开、1080p 可以跑；但 **Unreal 编辑器 + Pixel Streaming 编码 + 浏览器同时跑**，8 GB 显存和 4 GB 可用内存很容易爆。
- Web/Three.js 用同一块 GPU 的 WebGL2，1080p 地形+ hazard 面+粒子没问题；不占 Unreal 的显存/内存。
- 因此：**本机实时 Unreal Pixel Streaming 不推荐**；Unreal 只做离线出片（同一帧数据）。

## 二、选型结论

### 主路线（推荐，按“最好且能落地”）

```
Python Q4/Q3 求解器（本地 CPU）
  → 帧数据 h/u/b_dep + Q3 预警时间线
  → Web 3D（Three.js）交互沙盘
  → Cloudflare 临时隧道分享链接
  → ffmpeg 导出 1080p 视频/报告
```

- **交互 + 分析 + 汇报画面并重**：Web 端做参数、剖面、图层、时间轴；Three.js 做地形/水面/粒子/电影机位；ffmpeg 出片。
- **浏览器分享**：`cloudflared tunnel --url http://localhost:8000` 生成 `https://xxx.trycloudflare.com`；免费、无需账号，但机器要开着、URL 会变。
- **稳定链接**：Cloudflare 免费账号 + named tunnel，或把预计算场景部署到 Cloudflare Pages/Netlify（静态、无后端）。

### 备选（不推荐现在做）

- **Unreal 实时 Pixel Streaming**：需要 GPU 服务器；本机 8 GB VRAM + 4 GB 可用内存不够稳；云 GPU 要付费。
- **Unreal 离线电影级**：可行，但需装 UE5（~100 GB）和资产；放在 Web v1 之后做，3–5 人天。
- **CesiumJS**：需要 Ion token/3D Tiles；本地 DEM 用 Three.js 更直接，暂不需要。
- **PyVista**：只作离线验证，不做沙盘。

## 四、操作路线（按人天）

### P0：地形沙盘 v0.1（2–3 人天）

1. `export_sandbox.py`：DEM 降采样 4×、坡度、主沟、冰川掩膜、事件/口岸 marker → JSON/binary。
2. `web/`：Three.js 地形 mesh + 顶点色 + 主沟 ribbon + 冰川源区 + 标签。
3. 本地 `python -m http.server`/Vite；Chrome 打开。
4. 接 Q3 预警时间线（静态）。
5. 用 `cloudflared` 生成临时分享链接。

**验收**：浏览器能旋转/缩放/看地形/看主沟/看 Q3 时间线；手机/另一台电脑可通过链接打开。

### P1：Q4 帧 + 参数（3–5 人天）

1. 把 Q4 2D HLL/Voellmy 求解器落到 `03_编程手/Q4/源代码/`；V1–V12/13 项检查。
2. 30 m 走廊网格；输出 `h/u/b_dep` 帧（PNG/二进制）。
3. Web 接帧：时间轴、播放、参数（V0/μ/ξ/网格）、剖面、图例。
4. 质量守恒/零动量/Ritter/网格收敛角标；未过红标。

**验收**：改参数能重跑一个场景；帧与 Q4 结果一致；质量守恒 <1%。

### P2：Q3 联动 + 汇报画面（2–3 人天）

1. Q3 集合/预警时间线叠加；分支频率、lead 区间、`p_inf`。
2. 电影机位/自动巡航/关键帧；Three.js 水 shader/粒子/雾。
3. ffmpeg 导出 1080p 视频；一键截图。
4. Cloudflare named tunnel 或静态部署。

**验收**：同一场景可“交互分析”和“出片”；分享链接可用。

### P3：Unreal 离线电影级（可选，3–5 人天）

1. 装 UE5（E 盘，关闭 Lumen 全开/降低阴影）。
2. 导入同一地形/帧数据（高度图/纹理/顶点动画）。
3. 只渲染选定 2026 情景；不接实时参数。
4. OBS/Sequencer 出片。

> 只有 P2 完成后才做；不要先装 UE5 再发现物理/数据没接好。

## 五、降级条件

| 情况 | 降级 |

| 内存不足/求解器太慢 | 60/90 m 走廊；预计算帧；只跑 2026 基线 |

| 没有建筑/道路/影像 | 山谷尺度，不做街道级 |
| GPU 不够 Pixel Streaming | 不做实时 Unreal，只离线出片 |

## 六、现在开工的顺序

1. **不装 UE5**；先做 Web v0.1。
2. 安装 `three`、`vite`、`fastapi`、`cloudflared`（免费）。
3. 用现有 30 m DEM 出地形；接 Q3 时间线。
4. 再落 Q4 求解器，替换“预览波前”。
5. 最后才考虑 Unreal 离线出片。

---

*一句话：这台机器能跑“Web 3D 交互 + 本地 Q4 求解 + 浏览器分享”，不能稳跑“Unreal 实时串流”。按 Web 主路线做，Unreal 只做离线电影级。*
