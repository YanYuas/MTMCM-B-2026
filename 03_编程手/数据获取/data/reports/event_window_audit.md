# 事件窗口数据核对（2026-08-26 10:30）

> 窗口：事件前 72 小时，2026-08-23 10:30 → 2026-08-26 10:30（北京时间）
> 目的：用三套独立来源核对“灾前到底下了多少雨”，避免把站点零降雨当成“没有水源”。

## 1. 降水对照

| 来源 | 变量 | 有效小时 | 缺测 | 累计 | 最大 | 非零小时 |
|---|---|---|---|---|---|---|
| TPDC-01 站点 | `Precip(mm)` | 72 | 0 | 0.00 mm | 0.00 mm | 0 |
| Open-Meteo（ERA5） | `precipitation` | 72 | 0 | 0.70 mm | 0.20 mm | 6 |
| NASA POWER | `PRECTOTCORR` | 72 | 0 | 8.46 mm | 0.91 mm | 58 |

## 2. 站点气温（同一窗口）

- `Ta_2m`：有效 72 小时，缺测 0，均值 13.25 °C，最大值 20.80 °C。

## 3. 结论（写论文时直接用）

1. **站点在灾前 72 小时累计降水为 0.00 mm**（有效 72 小时）；这与“站点暴雨触发”叙事不一致，不能把本站降水当作灾害触发证据。
2. **再分析网格给出非零降水**（Open-Meteo 0.70 mm，NASA POWER 8.46 mm），说明“站点零降雨”不等于“源区没有水源”；源区在尼泊尔一侧，站点距口岸约 65 km。
3. 三套来源的空间代表性不同：TPDC-01 是单点观测，Open-Meteo/NASA POWER 是网格再分析；网格海拔约 4138 m / 4995 m，与站点 4140 m 不同。论文中必须标注“观测/再分析/预报”的证据等级。
4. 这段核对支持 Q1 的“事件窗口异常”写法：先证明站点没有强降水，再去找边界层/土壤/辐射信号；也支持 Q3 的“预警不能只看本站雨量”，需要卫星/源区降水或冰崩信号。

## 4. 复现

```powershell
python -m mtmcm_data fetch tpdc_01_hourly open_meteo_archive nasa_power
python -m mtmcm_data audit
```

> 注意：TPDC-01 的 `9999.9` 按缺测处理；站点时间原始格式无前导零，已按 `YYYY-M-D H:MM` 解析。
