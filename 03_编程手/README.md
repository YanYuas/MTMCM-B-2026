## 编程手纪律（铁律）

1. **不自行改模型假设**。有问题先写 `理论问题反馈.md`，按 P0/P1/P2 分级。
2. **先跑验证题，再跑真实验**。验证题（已知答案）不过，不跑大实验。
3. **每步代码写【思路】标注**：写"为什么这么做"，不只是"做了什么"。
4. **固定随机种子、多次运行取最优**。
5. **自检必须真能失败**：断言失败必须非零退出，禁止 try/except 吞掉、禁止"近似免责"。
6. **图的数值只能来自模型**，禁止硬编码、禁止编造。弃用图立即移出交付目录。
7. **叫"独立验证"必须真独立**（不同人/不同语言/不调对方代码）。
8. **报告"已改"以文件 hash/mtime 为准**；核验方先查文件再信报告。
9. **脚本名用 ASCII**（中文路径在 .bat 会被 cp936 拆行）。
10. **含队号/姓名的文件提交前必须脱敏**。

## 每问标准交付物

每问 `Q?/` 目录下：

| 文件/目录 | 内容 | 必选 |
|---|---|---|
| `00_交付清单.md` | 做了什么、结果在哪、哪些没做 | ✅ |
| `源代码/` | 源代码（每步【思路】标注） | ✅ |
| `实验结果/` | 实验数据 + 图 | ✅ |
| `理论问题反馈.md` | P0/P1/P2 分级反馈 | 有问题时 |
| `验证题结果.md` | 验证题跑通记录 | ✅ |
